# Общие правила разработки (Next.js, @tanchu/agent-rules)

Общие для всех проектов на Next.js правила. Правила конкретного проекта — в его `AGENTS.md`;
если они противоречат этим, прав `AGENTS.md` проекта.

## Стек

Next.js (App Router) + React + TypeScript, Tailwind CSS v4 или CSS Modules, next-intl,
Playwright, pnpm. Общие конфиги — пакеты `@tanchu/eslint-config`, `@tanchu/stylelint-config`,
`@tanchu/tsconfig`; общий CI — `tanchu/dev-standards/.github/workflows/next-ci.yml`.
Сервер, порты, домены и деплой — приватный репозиторий `tanchu/infra`.

## Версии пакетов

Ставь последнюю совместимую версию (`npm view pkg version` перед установкой), а не версию
из памяти. Если последняя ломает peer-зависимость — фиксируй совместимую и пиши в коммите почему.

## CI и выпуск

- Проверки идут на каждом PR и прямо перед выпуском (деплой по тегу `v*`, публикация в npm).
  На push в `main` не запускаются: код попадает в `main` только через PR с зелёным CI.
- Branch protection на бесплатном плане нет: мержи PR только после зелёного CI.
- Выпуск — тег `v*` на коммите из `main`; деплой сам прогоняет все проверки и выкладывает
  ровно этот коммит. Откат — Re-run деплоя у старого тега.

## Lint и typecheck — только при изменении кода

Если в `git diff --name-only` нет `.ts`/`.tsx`/`.css`, локально lint и typecheck не гоняй:
CI всё равно проверит.

## Структура

- Файлы, нужные одной странице, живут рядом с ней в `_components/` (App Router не считает
  папку с `_` маршрутом). В общие `src/components/`, `src/lib/` — только то, что нужно
  нескольким маршрутам.
- Один TSX-компонент на файл; хелперы, типы и константы могут жить рядом с ним.
- Компонент длиннее 300 строк — сигнал разбить (ESLint предупреждает). Если разбивать
  нет смысла — комментарий в начале файла почему.
- По умолчанию Server Components; `"use client"` — только когда нужны хуки, обработчики,
  браузерные API, и как можно ниже по дереву.
- Компоненты — именованные экспорты (`export function X`); `export default` — только
  файлы Next (`page.tsx`, `layout.tsx` и т. п.).
- React-типы импортируй напрямую: `import type { ReactNode } from 'react'`, не `React.ReactNode`.
- Избегай лишних `useEffect`: вычисляй состояние при рендере, данные получай на сервере.

## Стили

- **Tailwind CSS v4**: только классы из шкалы (`gap-y-15`, не `gap-y-[60px]`), брейкпоинты
  только в rem — именованные из `@theme` или `min-[NNrem]:`, размер шрифта только чётный.
  Tailwind сортирует брейкпоинты в px и rem не по значению, поэтому px-брейкпоинт может
  перебить rem-брейкпоинт. Классы в константах называй `*_CLASS`, `*_CLASSES`, `*_SIZE`,
  `*_COLOR`, `*_STYLE(S)` — так их проверяет линтер. Всё это проверяет ESLint и часть
  исправляет `eslint --fix`.
- **Без Tailwind** (обычный CSS / CSS Modules): имена классов по BEM в kebab-case —
  `block`, `block__element`, `block--modifier`; проверяет stylelint.
- **Цвета — только OKLCH** (`oklch(39.45% 0.0367 150.51)`, прозрачность `oklch(… / 50%)`),
  через токены `@theme`/переменные; не hex/rgb/hsl и не прямо в классе (`bg-[#…]`).
- **Единицы**: размер шрифта, отступы и брейкпоинты — `rem`; межбуквенный интервал — `em`;
  межстрочный — без единиц; `px` — для рамок, теней и «волосяных» деталей.
- Без `!important`.

## Браузеры

Поддерживаемые браузеры — `@tanchu/browserslist-config` (`"browserslist": ["extends
@tanchu/browserslist-config"]` в `package.json`): минимум Tailwind v4 — Chrome/Edge 111,
Safari 16.4, Firefox 128 — с мобильными версиями.
API, которого нет хотя бы в одном браузере из списка, включай только с проверкой поддержки
и рабочим поведением без него (полифилл, подгружаемый только там, где нужен, или упрощённый
вариант). `eslint-plugin-compat` ловит API из своей базы; совсем новые API он не знает —
проверку поддержки для них пиши сам.

## Доступность

WCAG 2.2 AA: строгий `jsx-a11y` в ESLint, axe в E2E-тестах. Текущий пункт меню —
`aria-current="page"` и не только цветом.

## Тесты

- E2E — `tests/e2e/` (Playwright), компонентные — рядом с компонентом (`*.spec.tsx`).
- Page Object для сложных страниц; локаторы — `getByRole`/`getByText`/`getByLabel`.
  `data-testid` в нотации BEM (`cookie-banner__accept`) — только там, где текст зависит от
  языка, и только когда он нужен тесту. В продакшен-сборке `data-testid` вырезается
  (`compiler.reactRemoveProperties`).
- Без `page.waitForTimeout()`: жди элементы, текст, ответы сети; web-first утверждения.
- Внешние API в E2E — заглушки (`page.route()` или локальный stub-сервер).
- Эталон вычисленных стилей (`computed-styles.spec.ts`) ловит сдвиги вёрстки дешевле
  скриншотов. Рефакторинг должен проходить без изменений эталона; намеренная правка
  вёрстки — `--update-snapshots` и проверка diff в PR.
